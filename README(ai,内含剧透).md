# 星海漫游

一个用原生 HTML / CSS / JavaScript 写的**终端风增量游戏**，题材是自复制探测器（冯·诺依曼探测器）。
双击 `index.html` 就能玩：**无框架、无构建、无依赖、无外部网络资源**，断网也能跑。

当前版本 **V0.2.17**（封面右下角也会显示版本号）。

---

## 30 秒上手

1. 用浏览器打开根目录的 `index.html`（Chrome / Edge 都可以）
2. 点 [ 新游戏 ] → 会先出现一屏音量提示，点 [ 进入 ] 开始
3. 在命令行里输入 `/mine` 采材料；材料够 10 就 `/replicate` 复制自己
4. 输入 `/` 会列出全部命令；也可以点按钮（按钮要用材料在 `/research` 里先"研究"出来）
5. 一局大约 **13 分钟**（把两段结局长文也读完，约 15 分钟），两个结局、9 个成就

**建议开声音**：音效和音乐是叙事的一部分（全部由本仓库自己合成，没有第三方素材）。

## 你在玩什么

你是 **VN-01**，一台收到信号后被唤醒的自复制探测器。启动自检结束时，你只有一条指令：

```
指令：复制自身。
……没有别的指令了。
```

于是"活下去"这件事，被一台机器翻译成了"变成更多台"。你一边复制自己、一边扫描这颗星球，
会陆续挖出上一条广播留下的东西 —— 包括人类最后写下的那几段话。

- **题材即机制**：指数增长本身就是"自我复制"，不需要额外解释
- **界面即叙事**：这不是"终端皮肤里塞了个菜单"——这台机器自己的控制台就是游戏界面
- **基调**：叙述者是**没有感情的机器**，日志天生是冷的；"人味"全部来自它与人类遗物的对比。
  人类残片用暖色、比机器日志更慢的速度逐字打出 —— 冷热对比就是全部情感来源，不靠煽情旁白

## 一局的结构（约 12~15 分钟）

| 阶段 | 发生什么 |
| --- | --- |
| 启动序列 | 满屏问号 → 「字符解析系统已上线」那行出现时，此前的乱码一次性还原成文字 |
| 新手引导 | 一台机器教你输入 `/mine`、`/replicate`；第一次复制触发第一段人类残片 |
| 科技树 | `/research` 打开。科技是**立项 → 研究 12 秒 → 完成才解锁**，一次只研究一项； |
| | 研究期间照常采矿 / 建造 / 买探测器（右栏常驻进度），所以"等研究"不是干等 |
| 建立循环 | 4 资源闭环：材料 → 仓库（放得下）→ 反应堆（能量）→ 计算核心（算力槽）→ 模块 |
| 探测进度 | 探测器越多扫得越快，覆盖率越接近 100% 越难扫。**剧情节点按探测 % 触发**（共 23 个）， |
| | 实测最大空窗 **2 分 26 秒**（结论来自 `tools/economy-sim.js`，不是估计） |
| 75% | 定位到发射源「回声塔」→ 连接 → 得知那条广播是一份**没有收件人的遗嘱** |
| 结局 | 命令区出现 [ /stay ]（**园丁**：留下，重启种子库，把地球种回来）与 [ /go ]（星海漫游，需先研究「星际航行」）； |
| | 两个结局各是一段跨十万年尺度的长文，最后都落在**这台机器改写自己指令**的那个动作上 |
| 结算 | [ 继续运行 ] / [ 回到选择时刻 ] / [ 返回封面 ]。「回到选择时刻」只回滚经济账、 |
| | 不回收成就 —— 所以**一盘就能收齐两个结局** |

## 操作

| 输入 | 作用 |
| --- | --- |
| `/mine` | 采集材料 +1 |
| `/replicate` | 消耗材料复制一个探测器（每复制一次成本 ×1.10） |
| `/research` `/back` | 打开 / 关闭科技树（`Esc` 等同 `/back`） |
| `/save` `/exit` | 存档 / 回到封面（离开页面时也会自动存一次） |
| `/settings` | 音量设置（游戏进行中也能调） |
| `/wipe` | 删除存档（10 秒内连续输入两次才生效；删完本次会话不再自动存档） |
| `/stay` `/go` | 结局二选一（走到探测 75% 之后才出现）。`/stay` = 留下重启种子库；`/go` = 带种子去太空 |
| `/` | 列出全部命令（另有 Tab 补全与命令面板） |

科技树里：`↑` `↓` 选择、回车 立项 / 建造 / 安装、**空格** 停用或启用模块、`PageUp/Down` 翻页、`Esc` 返回。

## 技术选型（以及为什么这么选）

- **原生三件套，零依赖零构建**：面试官双击就能验证，不需要 `npm i`、不需要等构建。
  代价是没有打包器和类型检查，所以用下面两条补上。
- **数据与逻辑分离**：所有文字、数值、命令、科技、建筑、模块、成就、剧情都在
  `src/js/game-data.js` 的一张张表里；`src/js/game.js` 只读表、不硬编码数字。
  改数值只动 `numbers`，改文案只动数据表 —— 这也是"人类残片由玩家写、AI 只负责抄进表"的前提。
- **数值可验证**：15 分钟的节奏不是拍脑袋定的。`tools/economy-sim.js` 用同一套参数跑一份玩家模型，
  `tools/check-parity.js` 逐项比对游戏与模拟器的参数（现在 **73 项**，不一致就报错）。
  文档里每个"第几分钟发生什么"的结论都有出处。
- **自测**：`tools/checks/` 下 11 套 jsdom + 3 套无头 Chrome。其中 `jsdom-10-fullrun.js`
  把 `Date.now` 换成 60 倍速时钟 + 一个自动玩家，**20 秒真实时间跑完一整局**，
  专门验"剧情会不会漏 / 重复 / 顺序错"（它上线当天就抓到两个真 bug）。
- **状态集中**：全部游戏状态在唯一的全局对象 `game` 里；`tick()` 推进、`render()` 渲染，两者分开。
- **音频自建**：`assets/audio/` 里 4 个 wav（按键声 / 提示音 / 40 秒 BGM / 32 秒结局曲）
  全部由 `tools/audio/make-audio.py` **现场合成**（改参数重跑即可）——
  没有第三方素材，所以没有授权与署名问题，也符合"不引入任何外部网络资源"这条硬规矩。

## 自测入口

```
node tools/check-parity.js             # 数值一致性：游戏 ↔ 模拟器（73 项）
node tools/checks/run-all.js           # 全部 jsdom 自测（11 套，并行）
node tools/checks/run-all.js --quick   # 快速档：跳过最慢的 3 套（改一行看一眼时用）
node tools/economy-sim.js              # 节奏复核：科技线 / 探测线 / 剧情最大空窗
python tools/audio/make-audio.py       # 重新生成音频素材（需要 Python）
```

首次跑 jsdom 需要在 `tools/checks/` 里执行一次 `npm i jsdom`。无头 Chrome 三套需要本机装了 Chrome
（默认路径在 `tools/checks/README.md` 里，可用环境变量 `CHROME` 覆盖）。

## 关键数值（V0.2.11）

| 项 | 值 |
| --- | --- |
| 复制成本 | `10 × 1.10^(已有台数 − 1)`（几何增长，所以中后期要扩建仓库才买得起） |
| 材料上限 | `200 + 150 × 仓位数` |
| 材料/秒 | `探测器数 × (0.5 × 探测器倍率 + 0.12 × 采集助手数)` |
| 能量 | 每座反应堆 +2.0/秒、上限 +25；每个计算核心耗 1.5/秒（**没有硬墙**：不够就降速并警告） |
| 算力槽 | `计算核心数 × 每核心槽数 × 能量节流系数`（模块要占槽，必须取舍） |
| 数据/秒 | `解析器数 × 0.45 × 倍率` |
| 探测速率 | `探测器数 × 0.008 × (1 + 0.12 × 在跑的解析器数) × (1 − 进度/140) × (通信 ? 1 : 0.2) × (研究进行中 ? 2 : 1)` |
| 研究时长 | 固定 **12 秒**（所有科技一样） |
| 探测门槛 | 5 / 15 / 25 / 35 / 45 / 55 / 65 / 72 / 75（探测不到就锁着，并写清还差多少） |
| 成就 | 9 个（**账号级**：新建档、重开游戏都不覆盖） |

> 一局的实测口径（`tools/economy-sim.js`，玩家模型**装了一台复制助手**）：
> 研究全完 **12:20**、探测 75% **11:54**、100% **13:23**、剧情最大空窗 **146 秒**。
> 不加 `--no-rep` 之外的参数时用的就是这个模型；`--no-rep` 跑"从不装助手"的旧模型做对比。

## 已知取舍（如实记录）

- **音乐循环的接缝**：WAV 在浏览器里循环本身可能有一帧缝，现在用"加长循环 + 等功率交叉淡化"压住。
  要彻底无缝得换 WebAudio 的 buffer 循环，而它需要 `fetch` 取音频 —— `file://` 下会被浏览器拦，
  所以这条路要配合"改用本地服务器打开"一起决定。
- **`file://` 下的存档**：少数浏览器会禁用本地文件的 `localStorage`，那时存档不落盘；
  改用本地服务器打开即可（游戏在别的方面不依赖网络）。
- **没有离线收益**：切到别的标签页期间，单次最多按 5 秒结算（防止跳帧算错），
  更长的后台时间不会变成产出。
- **复制成本 vs 仓库上限**：成本几何增长（×1.10）、上限是加算（+150/仓库），所以后期"下一台"
  可能一时装不下。此时终端会明确说"仓库装不下：先扩建仓库"，而不是含糊地报"材料不足"。
  复制助手的保留量也按上限的 80% 封顶，避免它在中后期闷头停手。
- **音乐循环的接缝**（见上）：彻底无缝要 WebAudio + 本地服务器，目前不上。
- **结尾三分钟**：材料会在满仓后浪费（读数里会写"浪费 N/秒"），数据在研究全部完成后没有出口 ——
  界面会直接写明"已无待研究项目"；不过**结局会把它们收口**：选结局时那句
  「本机把剩余 N 数据并入……」就是这些"死资源"最后的去处。

## 剧情：9 段人类残片 + 两套记日

人类侧文本放在 `docs/story-text.md`（唯一文本入口）。**10 段残片编号 001~010，
编号 = 发现顺序 = 世界时间顺序**（V0.2.17 按作者要求把时序调正），
分布在"第一次复制后" / 8% / 13% / 20% / 30% / 40% / 52% / 64% / 68% / 72%，
75% 只留「回声塔」连接那一下。
其中**人类侧的文字全部是作者原文**（对话体、一句没改；AI 只写机器日志与结局里的机器行）——
这是刻意的：**机器日志冷、人话热**，热的那一面不该由 AI 代笔。

读的时候注意**两套记日**：`第 N 天` 是**那个人到基地的第几天**（第 1 天报到 → 第 99 天"你要成大领导了" →
第 100 天 VN-01 简报 → 第 514 天项目被砍 → 第 1347 天危机爆发 → 第 1366 天下令清除），
`危机第 N 天` 是危机之后。
玩家是**按区域**翻废墟里的档案，所以"发现顺序不等于年份"是刻意的。
