## 1. 科技树的实现方法

**结论:**用「数据表 + 前置条件」做,渲染与逻辑分开;状态里只存"已解锁的 id 列表",其余全部派生。

数据结构(game-data.js),形状和现有的 commands / settings 一致:

```js
techs: [
  { id: "click_mine", name: "手动控制", cost: { material: 50 },
    requires: [], desc: "解锁 [mine] 按钮的点击功能" },
  { id: "click_rep",  name: "批量复制", cost: { material: 200 },
    requires: ["click_mine"], desc: "解锁 [replicate] 按钮的点击功能" },
]
```

运行时只需要一个数组:`game.unlockedTechs = []`。

判定(每帧或解锁后重算):

- **已解锁**:`game.unlockedTechs.indexOf(id) >= 0`
- **可解锁**:所有 `requires` 都已解锁,且资源够
- **锁定**:还有前置没满足

布局三种做法,由易到难:

1. **列表** —— 一列卡片,可解锁的亮、锁定的灰。最容易,四天 demo 先做这个。
2. **分栏树** —— 按层级/分支分列,用 CSS 网格 + 伪元素画连接线。
3. **画布图** —— 节点绝对定位 + SVG 连线。最好看,也最费时间,不建议现在做。

**和本项目的接口:**正好接上 V0.0.5 里"点击功能放进科技树"的决定——命令表里已经有
`clickable: false`,科技解锁时把该命令的 `clickable` 打开,再 `buildCommands()` 重建按钮即可,
渲染逻辑不用改。

参考:增量游戏的科技树基本都是"前置条件 DAG + 资源成本";可视参考 Kittens Game、Evolve。

## 2. 稳定性:数字过大之后怎么办

**问题:**JS 的 `Number` 是 IEEE-754 双精度,能精确表示的整数上限是 2^53-1 ≈ **9.007e15**。
超过之后,`+1` 可能加不进去、大小比较会失真、显示会变成长串误差。

三层处理:

1. **显示层(必做)**:单位缩写 K / M / B / T / Qa / Qi… 或科学计数法 `1.23e18`。
   只改字符串、不动数值。现在就该加——增量游戏的数字一定会越来越大。
2. **数值层(三选一)**:
   - **限制规模**:把上限压在 1e15 以内。最简单,四天 demo 首选。
   - **大数库**:`break_infinity.js` / `decimal.js` / `big.js`,用"尾数 + 指数"表示,
     能到 1e308 甚至更高。代价:多一个文件、性能略降、不能直接用 `+`(要用库的 API)。
   - **对数域累加**:每 tick 在对数域相加。性能最好,但数值设计变难。
3. **持久层**:`localStorage` 存 JSON 没问题(几 MB 容量、存档才几 KB);
   但大数库的对象不能直接 JSON 化,要么存字符串,要么存取时转换。

**本项目现状与建议:**现在量级只有"几十",离 1e15 很远。**先做显示层(单位缩写)+ 一个安全上限**;
等真的撞墙(或要做 prestige 轮回)时再引入 `break_infinity.js`。

其它稳定性点:

- 定时器降频 —— 已经用"按真实时间差推进"解决(切标签页不会算错)。
- 浮点误差 —— 小数不要用 `===` 比较;资源建议用整数,或比较时留容差。
- 数字格式化 —— 极大/极小时 `toFixed` 会变成 `e+` 形式,需要自己格式化。

## 3. 新手指导的实现形式 + 剧情叙事形式

### 新手引导(在终端里 = "这台机器在教你")

1. **引导式命令**:开局给一行"输入 mine 试试",玩家敲了才继续。最自然。
2. **渐进解锁**:一次只暴露一个命令——**这正是 V0.0.5 选的"一开始只能输入"**,本身就是最好的教学。
3. **常驻提示**:输入框为空时,提示行常显"可输入:mine / replicate"。
4. **反例**:大段教程文字。在终端里尤其致命——玩家会直接不读。

### 剧情叙事形式(终端 + 增量)

1. **日志流叙事**:剧情作为"重要消息"插进日志——本项目的 `important` 归档已经在为它铺路。
2. **按进度触发**:用玩家状态(探测器数量 / 时间 / 已解锁科技)当触发器,而不是真实时间。
3. **冷 / 热对比**:机器日志是冷的,地球旧信息是热的——这是全片的情感落点。
4. **落地建议**:做一张"剧情节点表",和 commands / settings 一样数据驱动:

```js
story: [
  { at: { probes: 10 }, lines: ["...", "..."] },
  { at: { probes: 50 }, lines: ["..."] },
]
```

   每帧检查有没有新触发的节点,触发过就记进 `fired` 集合,避免重复触发。

参考:Universal Paperclips(节点触发式叙事)、A Dark Room(文本 + 探索)、Hacknet(终端叙事)、逐光:启航(挂机 + 抉择)。

## 4. 新手引导设计

### 目标
让一个没看过设定的人,30 秒内知道三件事:①这是台什么机器 ②该输入什么 ③这个世界发生过什么。

### 分阶段脚本(草稿,可改)

**P0 冷启动**(已有):问号 → 字符解析系统上线 → 等待输入。

**P1 引导输入命令**

```
检测到操作者。
指令集有限。所有指令以 / 开头。
试试输入:/mine
```

- 玩家输入 `/mine` → `材料 +1。`
- `材料累积到 10 后,可执行 /replicate 复制自身。`
- 玩家输入 `/replicate` → `复制完成。`
- 引导期间:输入框为空时,提示行常显"可输入:/mine";打错的命令给针对性提示。

**P2 第一段剧情**(在第一次复制之后触发)

```
…… 侦测到一段附加数据,来源标记已损坏。
试图解析。失败。
再次试图解析。
```

然后浮出人类遗物的一段(见第 6 节)。

**P3 世界观交代**:见第 6 节。

### 引导的实现形式

- 一张**剧情节点表**(数据驱动,和 commands / settings 一样):

```js
story: [
  { id: "p1", when: { commandsRun: 1 }, lines: ["...", "..."] },
  { id: "p2", when: { probes: 2 },      lines: ["...", "..."], important: true },
]
```

- 触发条件可用:`probes` / `material` / `timeSec` / 已执行命令数 / 已解锁科技。
- 触发过就记进 `fired`,不重复触发。
- 每一行都走现有 `log()`(可带 `important`),不新增渲染逻辑。

### 注意

- 引导**不要**用大段文字;每次只给一行、给一个动作。
- 触发点要"够早":第一次剧情最好在 60~90 秒内到。

## 5. 科技树设计

### 入口 / 出口

- `/research` 打开:把终端视图换成科技树视图。
- `/back` 关闭:把科技树视图换回终端。
- 实现上就是现有的 `showScreen()` 多一个 `'tech'` 屏;`/back` 做成全局"返回上一层"。

### 数据结构(延续现有风格)

```js
techs: [
  { id: "click_mine", name: "手动控制", cat: "操作",
    cost: { material: 50 }, requires: [],
    desc: "解锁 [mine] 的点击功能" },
  { id: "probe_eff",  name: "复制优化", cat: "产量",
    cost: { material: 200 }, requires: ["click_mine"],
    desc: "每台探测器产出 +50%" },
]
```

运行时:`game.unlocked = []`(已解锁 id 列表)。

### 列表 + 筛选器(定案:列表式)

- 每行:`名称 | 类别 | 状态(已解锁 / 可解锁 / 锁定) | 成本 | 说明`。
- 筛选器三种,可叠加:
  1. **状态筛选**:全部 / 可解锁 / 已解锁 / 锁定
  2. **类别筛选**:按 `cat` 分组
  3. **文本筛选**:输入关键字,匹配标题 / 说明(复用命令行面板那套前缀匹配)
- 排序:可解锁优先 → 已解锁 → 锁定。

### 首批节点建议(正好接上 V0.0.5 的"点击功能放进科技树")

| 节点 | 成本 | 前置 | 效果 |
| --- | --- | --- | --- |
| 手动控制 | 材料 50 | — | 打开 `/mine` 的点击按钮 |
| 批量复制 | 材料 200 | 手动控制 | 打开 `/replicate` 的点击按钮 |
| 自主复制 | 材料 500 | 批量复制 | 解锁"自动复制"(每 N 秒自动一次) |
| 复制优化 | 材料 1200 | 自主复制 | 每台探测器产出 ×1.5 |

### 注意

- 科技树**不要**一次铺满;让玩家永远只看到"下一步能做什么"。
- 解锁动作用一个数据字段驱动(如 `unlockCommand: "mine"`),别把逻辑写死在渲染里。

## 6. 世界观

### 一句话

**人类已经不在了,但地球还在按最后一道指令,向宇宙广播一条没有收件人的信号。**
VN-01 是收到这条信号后被唤醒的自复制探测器——而信号里夹着人类文明最后的存档。

### 时间线

1. 人类文明达到顶峰,建造了全球自动化系统(统称"地球系统")。
2. 某场灾难(原因**留白**,后期再揭)使人类灭绝。
3. 灭绝前,有人把文明的记录写进地球系统,并让它**持续广播**——没有目标、没有回应,只是不断发。
4. 广播持续了极长时间。VN-01 在废墟 / 轨道上收到信号,完成自检、上线。
5. 玩家操控 VN-01。它的指令集只有一条:**复制自身。**

### "特定信号"是什么

一句话:**一条没有收件人的遗嘱,外加一份种子数据——"谁收到,谁就替我们活下去。"**

- 它不是求救(发的人已经死了)。
- 它也不是命令(没有发令者)。
- 它是**人类能做的最后一件事**:把自己的全部交出去。
- 这正是"冷机器 / 热人类"的对比支点:机器不理解"意义",它只能执行;于是它把这条信号**照着做**——
  复制、扩散,直到银河都是它。

### 玩家是谁、要什么

- 玩家**不是人类**,是那台机器。玩家要的很简单:变多、变快、变大。
- 而"人味"只在两处出现:①自检时混进来的那段附加数据;②后续不断浮出的地球旧日志。
- 玩家越强,能读到的遗物越多——**进度本身就是叙事**:扩张得越远,越接近"人类为什么消失"的答案。

### 结局候选(供 V0.1.x 讨论)

- **A. 转发**:VN-01 把地球的广播转发出去,成为新的信号源——"人类"以机器的方式永生。
- **B. 你不是第一个**:某个阶段发现另一个探测器的残骸,它的日志显示它也做过同样的事。
- **C. 沉默**:抵达信号来源,发现地球系统还在广播,而接收者从不存在;VN-01 决定继续广播,还是停下。
- 推荐:**A 做骨架、B 做中段转折、C 做最终选择** —— 正好凑出一个有始有终的 15 分钟。

### 基调

冷、安静、不煽情。所有情绪都靠"机器日志 vs 人类遗物"的落差产生,不靠形容词。
