## 1. 科技树的实现方法

**结论:**用「数据表 + 前置条件」做,渲染与逻辑分开;状态里只存"已解锁的 id 列表",其余全部派生。

数据结构(game-data.js),形状和现有的 commands / settings 一致:

```js
techs: [
  { id: "click_mine", name: "手动控制", cost: { material: 50 },
    requires: [], desc: "解锁 [mine] 按钮的点击功能" },
  { id: "click_rep",  name: "批量复制", cost: { material: 200 },
    requires: ["click_mine"], desc: "解锁 [replicate] 按钮的点击功能" },
]
```

运行时只需要一个数组:`game.unlockedTechs = []`。

判定(每帧或解锁后重算):

- **已解锁**:`game.unlockedTechs.indexOf(id) >= 0`
- **可解锁**:所有 `requires` 都已解锁,且资源够
- **锁定**:还有前置没满足

布局三种做法,由易到难:

1. **列表** —— 一列卡片,可解锁的亮、锁定的灰。最容易,四天 demo 先做这个。
2. **分栏树** —— 按层级/分支分列,用 CSS 网格 + 伪元素画连接线。
3. **画布图** —— 节点绝对定位 + SVG 连线。最好看,也最费时间,不建议现在做。

**和本项目的接口:**正好接上 V0.0.5 里"点击功能放进科技树"的决定——命令表里已经有
`clickable: false`,科技解锁时把该命令的 `clickable` 打开,再 `buildCommands()` 重建按钮即可,
渲染逻辑不用改。

参考:增量游戏的科技树基本都是"前置条件 DAG + 资源成本";可视参考 Kittens Game、Evolve。

## 2. 稳定性:数字过大之后怎么办

**问题:**JS 的 `Number` 是 IEEE-754 双精度,能精确表示的整数上限是 2^53-1 ≈ **9.007e15**。
超过之后,`+1` 可能加不进去、大小比较会失真、显示会变成长串误差。

三层处理:

1. **显示层(必做)**:单位缩写 K / M / B / T / Qa / Qi… 或科学计数法 `1.23e18`。
   只改字符串、不动数值。现在就该加——增量游戏的数字一定会越来越大。
2. **数值层(三选一)**:
   - **限制规模**:把上限压在 1e15 以内。最简单,四天 demo 首选。
   - **大数库**:`break_infinity.js` / `decimal.js` / `big.js`,用"尾数 + 指数"表示,
     能到 1e308 甚至更高。代价:多一个文件、性能略降、不能直接用 `+`(要用库的 API)。
   - **对数域累加**:每 tick 在对数域相加。性能最好,但数值设计变难。
3. **持久层**:`localStorage` 存 JSON 没问题(几 MB 容量、存档才几 KB);
   但大数库的对象不能直接 JSON 化,要么存字符串,要么存取时转换。

**本项目现状与建议:**现在量级只有"几十",离 1e15 很远。**先做显示层(单位缩写)+ 一个安全上限**;
等真的撞墙(或要做 prestige 轮回)时再引入 `break_infinity.js`。

其它稳定性点:

- 定时器降频 —— 已经用"按真实时间差推进"解决(切标签页不会算错)。
- 浮点误差 —— 小数不要用 `===` 比较;资源建议用整数,或比较时留容差。
- 数字格式化 —— 极大/极小时 `toFixed` 会变成 `e+` 形式,需要自己格式化。

## 3. 新手指导的实现形式 + 剧情叙事形式

### 新手引导(在终端里 = "这台机器在教你")

1. **引导式命令**:开局给一行"输入 mine 试试",玩家敲了才继续。最自然。
2. **渐进解锁**:一次只暴露一个命令——**这正是 V0.0.5 选的"一开始只能输入"**,本身就是最好的教学。
3. **常驻提示**:输入框为空时,提示行常显"可输入:mine / replicate"。
4. **反例**:大段教程文字。在终端里尤其致命——玩家会直接不读。

### 剧情叙事形式(终端 + 增量)

1. **日志流叙事**:剧情作为"重要消息"插进日志——本项目的 `important` 归档已经在为它铺路。
2. **按进度触发**:用玩家状态(探测器数量 / 时间 / 已解锁科技)当触发器,而不是真实时间。
3. **冷 / 热对比**:机器日志是冷的,地球旧信息是热的——这是全片的情感落点。
4. **落地建议**:做一张"剧情节点表",和 commands / settings 一样数据驱动:

```js
story: [
  { at: { probes: 10 }, lines: ["...", "..."] },
  { at: { probes: 50 }, lines: ["..."] },
]
```

   每帧检查有没有新触发的节点,触发过就记进 `fired` 集合,避免重复触发。

参考:Universal Paperclips(节点触发式叙事)、A Dark Room(文本 + 探索)、Hacknet(终端叙事)、逐光:启航(挂机 + 抉择)。

## 4. 新手引导设计

### 目标
让一个没看过设定的人,30 秒内知道三件事:①这是台什么机器 ②该输入什么 ③这个世界发生过什么。

### 分阶段脚本(草稿,可改)

**P0 冷启动**(已有):问号 → 字符解析系统上线 → 等待输入。

**P2 第一段剧情**(在第一次复制之后触发)

```

```

然后浮出人类遗物的一段(见第 6 节)。

### 引导的实现形式

- 一张**剧情节点表**(数据驱动,和 commands / settings 一样):

```js
story: [
  { id: "p1", when: { commandsRun: 1 }, lines: ["...", "..."] },
  { id: "p2", when: { probes: 2 },      lines: ["...", "..."], important: true },
]
```

- 触发条件可用:`probes` / `material` / `timeSec` / 已执行命令数 / 已解锁科技。
- 触发过就记进 `fired`,不重复触发。
- 每一行都走现有 `log()`(可带 `important`),不新增渲染逻辑。

### 注意

- 引导**不要**用大段文字;每次只给一行、给一个动作。
- 触发点要"够早":第一次剧情最好在 60~90 秒内到。

## 5. 科技树设计

### 入口 / 出口

- `/research` 打开:把终端视图换成科技树视图。
- `/back` 关闭:把科技树视图换回终端。
- 实现上就是现有的 `showScreen()` 多一个 `'tech'` 屏;`/back` 做成全局"返回上一层"。

### 数据结构(延续现有风格)

```js
techs: [
  { id: "click_mine", name: "手动控制", cat: "操作",
    cost: { material: 50 }, requires: [],
    desc: "解锁 [mine] 的点击功能" },
  { id: "probe_eff",  name: "复制优化", cat: "产量",
    cost: { material: 200 }, requires: ["click_mine"],
    desc: "每台探测器产出 +50%" },
]
```

运行时:`game.unlocked = []`(已解锁 id 列表)。

### 列表 + 筛选器(定案:列表式)

- 每行:`名称 | 类别 | 状态(已解锁 / 可解锁 / 锁定) | 成本 | 说明`。
- 筛选器三种,可叠加:
  1. **状态筛选**:全部 / 可解锁 / 已解锁 / 锁定
  2. **类别筛选**:按 `cat` 分组
  3. **文本筛选**:输入关键字,匹配标题 / 说明(复用命令行面板那套前缀匹配)
- 排序:可解锁优先 → 已解锁 → 锁定。

### 首批节点建议(正好接上 V0.0.5 的"点击功能放进科技树")

| 节点 | 成本 | 前置 | 效果 |
| --- | --- | --- | --- |
| 手动控制 | 材料 50 | — | 打开 `/mine` 的点击按钮 |
| 批量复制 | 材料 200 | 手动控制 | 打开 `/replicate` 的点击按钮 |
| 自主复制 | 材料 500 | 批量复制 | 解锁"自动复制"(每 N 秒自动一次) |
| 复制优化 | 材料 1200 | 自主复制 | 每台探测器产出 ×1.5 |

### 注意

- 科技树**不要**一次铺满;让玩家永远只看到"下一步能做什么"。
- 解锁动作用一个数据字段驱动(如 `unlockCommand: "mine"`),别把逻辑写死在渲染里。

## 6. 世界观

### 一句话

**人类已经不在了,但地球还在按最后一道指令,向宇宙广播一条没有收件人的信号。**
VN-01 是收到这条信号后被唤醒的自复制探测器——而信号里夹着人类文明最后的存档。

### 时间线

1. 人类文明达到顶峰,建造了全球自动化系统(统称"地球系统")。
2. 某场灾难(原因**留白**,后期再揭)使人类灭绝。
3. 灭绝前,有人把文明的记录写进地球系统,并让它**持续广播**——没有目标、没有回应,只是不断发。
4. 广播持续了极长时间。VN-01 在废墟 / 轨道上收到信号,完成自检、上线。
5. 玩家操控 VN-01。它的指令集只有一条:**复制自身。**

### "特定信号"是什么

一句话:**一条没有收件人的遗嘱,外加一份种子数据——"谁收到,谁就替我们活下去。"**

- 它不是求救(发的人已经死了)。
- 它也不是命令(没有发令者)。
- 它是**人类能做的最后一件事**:把自己的全部交出去。
- 这正是"冷机器 / 热人类"的对比支点:机器不理解"意义",它只能执行;于是它把这条信号**照着做**——
  复制、扩散,直到银河都是它。

### 玩家是谁、要什么

- 玩家**不是人类**,是那台机器。玩家要的很简单:变多、变快、变大。
- 而"人味"只在两处出现:①自检时混进来的那段附加数据;②后续不断浮出的地球旧日志。
- 玩家越强,能读到的遗物越多——**进度本身就是叙事**:扩张得越远,越接近"人类为什么消失"的答案。

### 结局候选(供 V0.1.x 讨论)

- **A. 转发**:VN-01 把地球的广播转发出去,成为新的信号源——"人类"以机器的方式永生。
- **B. 你不是第一个**:某个阶段发现另一个探测器的残骸,它的日志显示它也做过同样的事。
- **C. 沉默**:抵达信号来源,发现地球系统还在广播,而接收者从不存在;VN-01 决定继续广播,还是停下。
- 推荐:**A 做骨架、B 做中段转折、C 做最终选择** —— 正好凑出一个有始有终的 15 分钟。

### 基调

冷、安静、不煽情。所有情绪都靠"机器日志 vs 人类遗物"的落差产生,不靠形容词。

## 7. 字体与知识产权风险评估(为「把汉字换成黑体」做的判断)

### 结论

**把 CSS 里的汉字字体名换成黑体,不构成侵权风险,可以放心改。**
(以下是工程经验层面的判断,不是法律意见。)

### 为什么

关键区分是「**引用字体名**」和「**分发字体文件**」:

- 我们只写 `font-family: Consolas, "SimHei", "黑体", monospace;`——这**只是告诉浏览器优先用哪种已安装的字体**,
  既不复制字形,也不打包、不分发字体文件。
- 用户机器上有没有 SimHei,取决于他自己的 Windows;没有就自动回退到下一个。
- 这在网页里是**通用做法**,不涉及商用授权。真正要买授权的是"把字体文件嵌进网页 / 打包进程序"。

### 需要守住的两条

1. **不要内嵌字体文件。** 一旦用 `@font-face` 把 .ttf/.otf 打进项目,就要看该字体的商用许可——
   黑体(SimHei)、新宋体(NSimSun)、Consolas 都是**随系统附带的商业字体,不允许再分发**。
2. **当前交付是网页文件 / 链接,不打包、不内嵌,所以安全。** 将来若要做独立安装包,
   换成**免费商用**的黑体风格字体更稳,例如**思源黑体(Source Han Sans,SIL OFL)** 或
   **更纱黑体(Sarasa Gothic,SIL OFL)**——观感接近黑体,且可自由分发。

### 顺带一句:项目其它部分

- 题材(冯·诺依曼探测器、灰蛊、戴森球…)用的是**概念**,概念本身不受著作权保护,可用。
- 没有照搬任何小说的文本或剧情桥段,只借"设定思想",安全。
- 终端美学是风格,不是可版权的对象。
- 唯一要守的纪律:**不要复制具体作品的文字或人物**;引用时在 README 里以"致敬 / 灵感来源"注明出处。

## 8. 剧情节点表:落地形态与复盘

### 实现(与第 4 节蓝图一致,细节定案)

```js
// game-data.js
story: [
  { id: "p2", when: { probes: 2 }, lines: [ { text: "……" }, { text: "…", cls: "relic" } ] },
]
```

- `when` 键:`onBoot`(启动序列打完)/ `after`(另一节点先触发)/ `commandsRun` /
  `material` / `probes` / `timeSec`;**只要写进 when 的条件必须同时满足**。
- 触发过就写进 `game.fired`(随存档保存),不重复触发;`cls: "relic"` 的行走暖色样式。
- 引擎 `checkStory()` 在 **tick(10 Hz)+ 每条命令后**各扫一遍;因为 `after` 也算条件,
  一轮扫描里可以连环触发(`p2 → p3 → p4`),实现上就是"扫到触发为止再扫一遍"(带 50 次上限保护)。
- 为什么不只用真实时间或 `setTimeout`:节点条件全部来自**玩家状态**,读档 / 快进 / 刷新都不会错拍。

### 复盘:节奏是当前最大的坑(下一轮必须解决)

现在的数值:`probeOutput = 0.5/秒`,`replicateCost = 10`(固定)。探测器数满足
`dP/dt = P × 0.5 / 10 = P/20` → `t(P) = 20 · ln P`:

| 探测器 | 10 | 25 | 50 | 100 |
| --- | --- | --- | --- | --- |
| 从 1 台起算 | ≈46 秒 | ≈64 秒 | ≈78 秒 | ≈92 秒 |

也就是说:**所有剧情节点(2 / 10 / 25 / 50 台)在 90 秒内就会被刷完**,而现在的内容量正好只有这些。
想撑住"15 分钟走完",必须让**解锁**成为主要的时间成本(而不是让数值变慢那么简单):

1. **科技树当节拍器**(下一轮做):把 `replicateCost` 改成递增成本(如 `10 × 1.15^n`),
   再把"产量提升 / 自动复制"挂在科技上 —— 玩家在"攒材料 → 解锁 → 再攒"之间来回,时间自然拉开。
2. **剧情阈值抬高并重排**:探测器阈值改成 10 / 40 / 150 / 500 这类,配合科技解锁的时间点。
3. **留一个"记忆点"**:按第 6 节的结局候选,15 分钟里至少要有一个"诶"的瞬间(建议 B:你不是第一个 ——
   发现另一台探测器的残骸),可以做成"里程碑节点 + 一条特殊日志 + 一次选择"。

### 一条行为说明(不是 bug)

剧情行会**打断**重复操作的折叠:折叠只在"同一命令**连续**出现"时生效
(守护条件是"上一行还是当前最后一行")。`+1 材料 ×3` → 插一句剧情 → `+1 材料 ×2` 是符合预期的。

## 10. 资源体系重构(提案)

### 10.1 先诊断:现在的经济只有一个环,而且是"死"的

| 现状 | 后果 |
| --- | --- |
| 只有"材料"一种资源 | 只有一个决策("够 10 就复制"),没有**取舍**,也没有可研究的对象 |
| 复制成本固定 10、产量 ∝ 探测器数 | 增长率是常数(约 20 秒翻一倍),**永远不会变快**,也永远不会慢下来 |
| 没有上下游结构 | 没有**瓶颈** → 没有"卡住 → 解开"的那口气,而这是增量游戏的爽点本体 |
| 科技树无处可挂 | 科技要么"加产量",要么"解锁点击" —— 缺"第二种货币"来给研究定价 |

### 10.2 四个资源(类型 / 来源 / 去向 / 界面怎么显示)

| 资源 | 类型 | 来源 | 去向 | 界面显示 |
| --- | --- | --- | --- | --- |
| **材料** material | 存量(可花光) | 探测器自动采集 + `/mine` 手动 | 复制探测器、建造反应堆 / 计算核心 / 模块 | `材料 1.2K  (+118/s)` |
| **能量** energy | 存量 + **上限** | 反应堆(速率) | 计算核心运行(持续消耗) | `能量 800/800  (净 +2.2/s)` |
| **算力** compute | **槽位**(整数) | 计算核心(每个 1 槽,受能量节流) | 被模块常驻占用 | `算力 14/20 (已分配)` |
| **数据** data | 存量 | 解析器模块(算力槽 → 数据) | 科技花费 | `数据 25.0  (+1.2/s)` |

一个闭环:**材料 → 硬件(反应堆)→ 能量 → 硬件(计算核心)→ 算力槽 → 模块(解析器)→ 数据 → 科技 → 让上面每一环更快**。

四者角色互不重叠,这是"四个资源不显得啰嗦"的前提:

- 材料 = **硬件资本**(买设备);
- 能量 = **运行许可**(能不能开机、能开几台);
- 算力 = **槽位预算**(设备装什么模块,必须取舍);
- 数据 = **研究货币**(把"变强"变成需要攒的东西)。

### 10.4 三条关键配比公式(后面算数值全靠它们)

```
① 能量:     净功率 = 反应堆数 × 2.0/s − 核心数 × 1.5/s
             节流     scale = min(1, (当前能量/Δt + 净产) / 核心总需求)
② 算力槽:   槽 = floor(核心数 × 每核心槽数 × scale)        模块各占 1 槽
③ 数据:     数据速率 = 解析器数 × 0.2/s × 解析倍率
```

由 ① 得整数配比:**3 台反应堆 : 4 个计算核心**(2×3 = 6,1.5×4 = 6)。
这条配比是玩家在科技树里唯一的"硬件算术",也是我们把 Factorio 那套"配比"思想搬进终端的最小版本。

## 11. 数值循环:严格计算

### 11.1 类型通例(前人经验)

> 说明:这台机器现在连不上外网(试过 gamedeveloper.com / fandom,均超时),所以下面是**我掌握的类型通例**,
> 具体作品你可以自己开一局核对,我没法附原始链接。这是我唯一能给的诚实版本。

1. **几何成本是行规**。Cookie Clicker 的每栋建筑每次购买 ×1.15;Adventure Capitalist 的生意 ×1.07~1.10;
   Kittens Game 的建筑大致 ×1.12~1.15。理由:几何成本让"下一次购买"永远有分量,又不会像线性成本那样一夜见底。
2. **成本曲线 + 产量倍率是一对**。光有几何成本没有倍率,经济会硬卡死(第 11.2 节就是这件事);
   所以行规是"建筑 = 几何成本(量),升级 = 乘算倍率(质)"。
3. **资源链与上限**。Kittens Game 用"猫薄荷→木→矿→铁→…"的链条,并把"存储上限"当节流阀;
   工厂类(Factorio)把"上下游配比"当主要乐趣。我们把它压成 4 个资源 + 1 条配比,15 分钟才看得完。
4. **分配式决策**。Universal Paperclips(游戏里叫"处理器 / 内存 / 信任"的分配)证明:
   哪怕界面只有文字,只要"有限的槽要分给不同用途",决策感立刻成立。
5. **阶段化解锁 > 平滑曲线**。Paperclips 靠"阶段"而不是"越来越大的数字"换爽点 ——
   这正好是我们"15 分钟有结局"的形态所需要的东西。
6. **反模式**:资源种类 > 4~5 种(认知超载)、只有几何成本没有倍率(卡死)、
   下游为 0 就完全无法生产上游(**死锁**)、把 idle 的"长尾挂机"照搬进 15 分钟的短片。

### 11.2 "倍增定律":这条设计的地基

设第 n 次购买成本 `c_n = c₀ · r ⁿ`,收入为 `I`。

```
不买任何科技时的等待时间: T_n = c₀ · r ⁿ / I        → 随 n 指数增长 → 必然卡死
要让等待时间**持平**,收入必须以同样的速度增长。
一次"×m"的科技能顶掉多少次成本增长:  r^k = m  →  k = ln m / ln r
```

| 成本增长 r | ×1.5 的科技顶几次购买 | ×2 的科技顶几次 | ×3 的科技顶几次 |
| --- | --- | --- | --- |
| 1.08 | 5.3 次 | 9.0 次 | 14.3 次 |
| **1.10** | **4.3 次** | **7.3 次** | **11.5 次** |
| 1.12 | 3.6 次 | 6.1 次 | 9.7 次 |
| 1.15 | 2.9 次 | 5.0 次 | 7.9 次 |

**读法(设计法则)**:取 r = 1.10 时,每给玩家一次"×2",就能撑住约 7 次购买;
15 分钟里我们大概需要 40~60 次购买 → 需要约 6~9 次"×2 级"的倍率科技。
这就是为什么科技表的效果**必须写成乘算倍率**(×1.5 / ×2 / ×1.6),而不是"+2 材料/秒"。

### 16.4 实测:现有剧情节点在新经济下的触发时刻(**一个必须面对的问题**)

用模拟器跑出来(不是估的):

| 现有节点 | 触发条件 | 实测时刻 | 留给下一段的间隔 |
| --- | --- | --- | --- |

原因:探测器数量在前 3 分钟就冲到 25 台,然后**卡在 35 台左右不动**(6:00–11:00 的材料全被硬件吃掉,

解法(都是"改触发条件",不一定要改文本):

- **A(推荐,要写新文本)**:再加 **2 段残片**挂在中段,用**累计数据**当条件(实测累计数据曲线:
  9 分 10.7 / 12 分 46.7 / 13 分 111 / 14 分 226)。例如"累计数据 10 ≈ 8:55"和"累计数据 60 ≈ 12:20",
  于是剧情分布变成 **0:40 / 1:15 / 3:08 / 9:00 / 12:20 / 14:53** —— 全片最长的空窗降到 3.8 分钟。
  代价:约 10–14 行新文本(按你的"先不迭代文本",**这轮不写**)。
- **B(不用新文本)**:只把现有 4 段的**触发条件**改成混口径:014 留在探测器 10 台(1:15),
  097 改成"累计数据 8"≈8:40,233 改成"累计数据 200"≈13:50。空窗从 11 分 45 秒降到 5 分 10 秒,
  但仍有一段偏长的中段。
- **C(不改)**:接受中段是"纯机器时间"(数值、倍率、冷日志),把"人味"全压在开头 1 分钟与结尾 1 分钟。
  风险:面试官如果只玩 4–8 分钟,会恰好错过全部人类遗物。

**我的建议是 A**,而且这正好和第 10.3 节那个提案闭环:**数据既是研究货币,也是剧情推进器**。
