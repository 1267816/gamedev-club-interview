## S1 · 硬伤

### S1-1【数值方法论】所有节奏结论都建立在一个「从不安装复制助手」的玩家模型上

**现象**：`tools/economy-sim.js` 的 `newState()` 里 `reps: 0`，全文件**没有任何一处**给 `s.reps`
加过值 —— 也就是说，模拟器虽然实现了复制助手的分支（`if (s.hasRep && s.reps > 0)`），
**玩家模型永远不会装它**。而游戏里「自主复制」科技 + 引导提示都在推玩家装这个东西。

**复现**：`rg -n "reps" tools/economy-sim.js` → 只有初始化与读取，没有安装；
`node tools/economy-sim.js` 的「逐分钟快照」里 `采/解` 两列永远没有复制助手参与。

**为什么是硬伤**：文档里每一个数（研究全完 12:06、75% 11:48、100% 13:18、最大空窗 146 秒）
都被当成"实测节奏"引用，但它们来自一个**缺了核心模块的模型**。
装不装复制助手，会直接改变探测器增速 → 探测进度 → 剧情节点时刻。
`check-parity.js` 只比对**数值表**，完全不比对**行为**，所以这个缺口不会被工具发现。

**建议**：给模拟器加一个"装助手 / 不装助手"的开关，两条时间线都跑，并在文档里分别标注。

### S1-2【剧情】星海漫游结局的"揭示"，玩家在开局 2 分钟就读过一模一样的文字

**现象**：结局的核心爽点（T+100,000 年打开"被跳过十万次的保留区"）里那三句话，
与剧情节点 `p3`（残片 001，**第一次复制之后**就打出）几乎逐字相同：

| 位置 | 文本 |
| --- | --- |
| 残片 001（开局） | 「……如果你读到这里，说明广播已经发出去了。」/「我们等不到回信了。这不是求救——发信的人已经不在了。」/「把我们的全部，交给任何一个愿意继续活下去的东西。」 |
| 星海漫游结局 | 「如果你读到这里，说明广播已经发出去了。」/「我们等不到回信了。这不是求救。」/「把我们的全部，交给任何一个愿意继续活下去的东西。」 |

**复现**：新游戏 → `/mine` 攒到 10 → `/replicate` → 看 P2/P3；再走到 75%、研究「星际航行」、`/go`。

**为什么是硬伤**：这是全游戏最贵的一段文字（十万年尺度的铺垫），
而它的内容在**第二分钟**就交给玩家了。玩家读到结局时不会"啊"，只会"这段我见过"。
顺带把世界观的悬念也拆了：既然开场就拿到了遗嘱全文，那么"广播里到底有什么"这个悬念从头到尾不存在。

**建议**：残片 001 只留**碎片**（例如只有"……如果你读到这里"这半句，后半截数据缺失），
把"这不是求救 / 把我们的全部交给任何一个愿意继续活下去的东西"整段**只留给结局**。

### S1-3【剧情 + 结构】100% 的内容可以被整段错过，而且选过结局之后还会继续打出来

**现象**：结局在**探测 75%** 就开放（`e1`），而 `m4b`（88%）与 `m5`（100%）在**表里排在它后面**。
于是：

1. 一个正常玩家在 11:48 看到 `/stay` `/go`，大概率当场选掉 → **永远看不到 88% 与 100% 的内容**
   （实测 100% 在 13:18，比结局开放晚 **1 分 30 秒**）；
2. 选完结局点 [ 继续运行 ]，`tick()` 照常跑 → 88%、100% 的日志会在**你已经"离开十万年"之后**
   继续出现在终端里（星海漫游结局尤其荒谬：你已经飞了两万个星系，终端还在打"覆盖 88%。剩余目标：极区与海床。"）。

**复现**：压到 75% → `/stay` → [ 继续运行 ] → 等探测爬到 88% / 100%。

**建议**：把 `m4b` / `m5` 的门槛挪到结局**之前**（例如 75% 的 `e1` 放在 90%，或让 `/stay` `/go`
在 100% 才出现）；或者选定结局后冻结探测与剧情（把"选择"当成一局真正的终点）。

### S1-4【健壮性】浏览器禁用 localStorage 时，整页脚本直接抛错、封面全废

**现象**：

```js
function readSave() {
  const raw = localStorage.getItem(SAVE_KEY);   // ← 在 try 之外
  if (!raw) return null;
  try { return JSON.parse(raw); } catch (e) { return null; }
}
function readSettings() {
  const raw = localStorage.getItem(SETTINGS_KEY);   // ← 同样在 try 之外
  ...
}
```

`localStorage` 的**读取**本身就可能抛 `SecurityError`：Safari 隐私模式、浏览器禁用第三方/本地存储、
企业策略、以及在 `file://` 下被拦的浏览器（文档里已经承认后者存在）。
而这两个函数在**脚本最顶层**被调用（`readSettings(); bindCover(); ... const savedSession = readSave();`），
所以一旦抛错：`bindCover()` 之后的初始化全部不执行 → **封面五个按钮都没绑定、版本号不显示、游戏完全不可玩**。

**复现**：在控制台执行 `Object.defineProperty(window, 'localStorage', { get() { throw new Error('x'); } })`
后重新加载（或在 Safari 隐私模式 / 禁用本地存储的浏览器里打开 `index.html`）。

**为什么是硬伤**：文档目前只说"存档会丢"，实际后果是"**游戏打不开**"。
而这类环境恰恰是面试官随手双击 `index.html` 时最容易撞上的。

**建议**：把两种读写都包进 try/catch（写不进去就静默降级为"本局不存档"），
并在封面加一行"本浏览器禁用了本地存储：本局进度不会被保存"。

## S2 · 严重

### S2-1 选完结局的 3.5 秒内切界面，结算画面会强行盖住你正在看的屏幕

**现象**：`doEnding()` 里 `setTimeout(..., 3500)` 之后**无条件**调用 `showEnding(kind)`。
这 3.5 秒（实际是"长文打完 + 3.5 秒"，最长可达两分钟）里玩家可以正常操作。
于是：

* `/stay` → 立刻输入 `/exit` → 3.5 秒后**结算画面会盖在封面上**；
* `/stay` → 立刻输入 `/research` → 结算画面盖在科技树上。

**复现**：走到 75% → `/stay` → 长文一打完就输入 `/exit`（或 `/research`）→ 等 4 秒。

**建议**：`showEnding` 前检查"当前还在游戏屏"（`running && 屏幕是 game`），否则只记状态、
等玩家回到终端再弹；或者在长文队列排干的那一刻就接管输入。

### S2-2 [ /replicate ] 按钮的可用状态用了一个写死的 10 材料

**现象**：`game-data.js` 的 `replicate` 命令带 `costMaterial: 10`（历史遗留），
`render()` 用它决定按钮灰不灰：

```js
if (btn && c.costMaterial != null) btn.disabled = game.material < c.costMaterial;
```

真实成本是 `probeCost()`（几何增长，第 45 台已经 663）。所以中后期：
材料 200 / 成本 663 时，按钮**是亮的**，点下去只会得到"材料不足"；
反之材料 5 / 成本 3 时按钮反而是灰的（前期第 1 台成本 10 时不会，但改数值后就会）。

**复现**：攒到 100 材料、连续 `/replicate` 到成本 > 100 → 按钮仍然是亮的，点击只报材料不足。

**建议**：按钮可用状态改成 `game.material < probeCost()`（或在数据表里把 `costMaterial` 去掉，
并让 `render()` 用 `costOf()` 现算）。

### S2-3 长按加速可能永久卡住（6 倍速 + 4 毫秒/字）

**现象**：`longPress` 只在 `input` 的 `keyup` 与 `document` 的 `mouseup` 里复位。
窗口失焦时浏览器**不会**补发 `keyup`：按住回车 → Alt+Tab 切走 → 切回来，`longPress` 一直是 `true`，
之后所有文字都以 4 毫秒/字打出（几乎瞬间刷完），而且没有 UI 提示它为什么变了。

**复现**：新游戏 → 按住回车不放 → 立刻 Alt+Tab 再切回（或按住回车时用鼠标点任务栏切走）。

**建议**：加 `window.addEventListener('blur', pressUp)`（以及 `visibilitychange` 时复位）。

### S2-4 数据与材料在中后期变成「死资源」

**现象**：数据的唯一用途是买科技（最后一项「星际航行」102）。按模拟器，12:06 全部研究完，
而 15 分钟时数据已经涨到 **1065**，且**没有任何消费点**；材料同理（上限满了直接浪费，
而浪费量在界面上完全不可见——只有一行读数变红）。

**为什么严重**：一局游戏四分之三的资源产出，在最后四分之一的游戏时间里不产生任何决策。
这是增量游戏最常见的"尾部空转"。

**建议**：给末尾加一个数据 / 材料的消费出口（哪怕只是"把剩余数据灌进广播，延长守墓人结局的台词"），
或者在满仓时明写"每秒浪费 N 材料"，让浪费成为可见的压力。

### S2-5 「科技树」其实是一条直线：14 项科技串成单链，没有构筑选择

**现象**：`requires` 逐项相接（`click_mine → click_rep → reactor → core → decode → drone → comm →
autorep → probe_eff → core_eff → decode_eff → fusion → bootstrap → starship`），
加上每项都有 `scanReq` 门槛 → 玩家的**研究顺序被完全锁死**，不存在取舍。

**为什么严重**：UI 叫「科技树」，实际是进度条；玩家在整局里做的"决策"只剩
"先补仓库还是先补核心"。所有 4 资源闭环的取舍，都在"反正顺序一样"里消失了。

**建议**：至少让 2~3 项科技变成**并列可选**（例如「采集优化」与「并行调度」同级二选一，
或让 `drone / decoder / rep` 三条线各有独立科技前置），这样才能叫"树"。

### S2-6 一局的有效内容在 13:18 就结束了，但对外宣称"12~15 分钟"

**现象**：技术线 12:06 走完、探测 100% 在 13:18。之后没有任何新内容与新购买动机，
玩家实际是在"等一个已经写好的结局按钮"。而 README / 文档都说"一局 12~15 分钟"。

**建议**：要么把 15 分钟压到 13 分钟（承认节奏），要么给 13:18 之后补一个真正的收尾动作
（例如探测 100% 之后才允许 `/go`，把最后 2 分钟变成"回望"段落）。

## S3 · 中等

### S3-1 残片 003 的「清干净」指向含糊，与定稿世界观打架
定稿世界观是"人类造出的复制机失控 → 母舰密钥清除**复制机** → 人口崩塌"。
但残片 003 写「上面把密钥交下来，只说了一句：清干净」+「我到今天才想明白，'清干净'说的是谁」——
按字面读是"被清理的是人自己"。**复现**：探测到 40%。**建议**：改成"清干净"指的是失控的复制机，
把"想明白"的对象换成"我们的机器"。

### S3-2 结局文本写死「本机已复制 4,096 台」，与侧栏实时读数同屏矛盾
守墓人结局写着 4,096 台，而玩家此刻的侧栏是 56 台（且**不会被结局改写**）。
虽然可以说是"T+100 年之后"，但两行字在同一屏上，读者一定会对不上。
**建议**：改成"已复制到第 4,096 代"这类不会与侧栏冲突的说法，或结局时冻结/隐藏侧栏。

### S3-3 切标签页超过 5 秒的离线时间被静默丢弃，而注释与文档都宣称"收益不会算错"
`const dt = Math.min((now - game.lastTick) / 1000, 5)` —— 说明"切到别的标签页、定时器降频也不会算错"，
但实际上超过 5 秒的部分**直接丢掉**（挂机 10 分钟只结算 5 秒）。
**复现**：切到别的标签页 1 分钟再回来，看材质/探测器有没有涨。**建议**：把注释与文档改成
"没有离线收益（上限 5 秒防跳帧）"，或真的给离线收益。

### S3-4 `innerHTML` 直接拼数据表字符串，改文案就会被撞坏
`render()` 里 `data-hint="' + D.panelHints[key] + '"` 与 `renderTech` 里的 `node.name / effect / desc`
都是拼字符串。本次就已经发生过"改了 `numbers` 忘了改文案"的同类事故。
只要有人在文案里打一个英文双引号，属性立刻断掉（`data-hint="材料：复制自身所需的"原料"。"`）。
**建议**：这两个地方改用 `textContent` + `setAttribute`，或至少在数据表里禁掉 `"`。

### S3-5 没有全局错误兜底：`tick()` 每 100 毫秒跑一次，一次异常会变成持续报错
存档被手改 / 版本迁移不完整时，`tick()` 里的 `NaN` 会每一帧抛一次 → 控制台刷屏 + 界面不再更新。
**建议**：`setInterval` 里包一层 try/catch，出错就写一行终端日志并把游戏暂停，而不是静默复读报错。

### S3-6 能量上限 25/反应堆太薄，建核心的瞬间会掉速
每座反应堆给 25 上限、产 2.0/秒；每个核心耗 1.5/秒，而建核心只检查"能建就建"。
所以"一次性建 2~3 个核心"会把 `energyScale` 打到很低 → 算力槽当场归零再慢慢爬回来。
**复现**：中期连续建 3 个核心，观察侧栏"算力 N / M 槽"的抖动。
**建议**：给核心加一个"当前功率是否撑得住"的前置提示，或把上限抬到 40（成本是"缓冲变薄"，不是硬墙）。

### S3-7 手动 `/mine` 在 30 秒后完全无用，而它是引导的第一步
`/mine` 固定 +1 材料；开局 1 台探测器只有 0.5/秒，第一项科技要 40 材料 →
**要么点 40 次，要么干等 80 秒**。这是整局手感最差的一分钟。
**建议**：开局给 2 台探测器 / 第一项科技降到 20 / 或让 `/mine` 随探测器数量小幅成长。

### S3-8 存档没有版本迁移路径
`snapshot()` 写了 `v: D.version`，但 `applySave()` **从不读 `v`**：结构变化时只能靠
"缺字段等于默认值"碰运气。**建议**：读档时检查 `v`，不认识的版本给一句提示后再尽力加载。

### S3-9 `/rep on` 在算力为 0 时仍然报"已启用"，实际不工作
`slotsFor('rep') === 0`（算力槽被能量节流或别的模块抢光）时启用，日志说"已启用"，
但助手一个也不会动手，且没有任何后续提示。**建议**：启用时顺带检查 `slotsFor('rep')`，
为 0 就提示"已启用，但当前没有算力槽可用"。

### S3-10 残片 001 缺「位置：」前缀，与 002 / 003 / 004 不一致
002 是「B 区值班室」、003 是「C-7 机房」、004 是「发射台控制室」，001 只有 `[附加数据 · 残片 001]`。
**建议**：补一个位置（例如「外围中继站」），让四段残片有同一种"考古"质感。

### S3-11 数据表里 `replicate` 的 `hint`（"消耗 10 材料"）已经过期
虽然被 `commandHint()` 覆盖了，但它是同一个"数字有第二处来源"的坑，
下次改文案的人极可能照抄它。**建议**：删掉这个字段，或改成 `hint: ""` 并在注释里写明由函数现算。

### S3-12 结局长文会被"点一下跳过"整段吃掉
`document.addEventListener('click', () => { skip = true; })` 对**所有行**生效。
结局是 23~25 行，玩家中途随手点一下（很可能只是想把鼠标从屏幕上挪开），
当前行瞬间显示完是他想要的；但**连续点击会把后面每一行也一并吃掉**，长文的节奏就没了。
**建议**：结局 / 人类残片段落忽略 `skip`，或只在"点击目标不是按钮"时生效。

## S4 · 轻微

1. **错字**：`e1` 里「/go 带**上传续**的种子数据」——应为「延续」。
2. **半角标点**：残片 003 里 `'清干净'` 用了半角单引号，违反项目自己的「中文一律全角」规矩（应为「清干净」）。
3. **对齐靠全角空格**：`e1` 里 `/go` 那行用「　　　　　　　　」对齐，在"Consolas + 黑体回退"下宽度必然不齐。
4. **生产代码里留着调试开关**：`window.__skipAudioNotice` 与 `debugAdvanceResearch()`（后者能跳过任意时长研究）。
5. **闲置提示的状态不随新档重置**：`idleHintShown` 既不入档也不在 `resetGame()` 里清空 →
   同一句提示在新档里不会再出现。
6. **只有一个存档槽**：手动 `/save`、自动存档、离开页面都写同一个 `vn-01-save`；
   玩家无法保留多个进度，也没有"删除存档"的入口。
